| **Message shape** | one finding per unprotected agent, naming the adapter and the file to edit |

## What it checks

GM002 is an absence rule. For each of the three agents whose shared configuration can express a path-level read protection, it fires once when that agent is present in the repository (it has a project- or local-scope artifact) and no project-scope rule protects `.env` or `.env.local` (a rule covering either one counts):

| Agent | Counts as protection | Message |
|---|---|---|
| Claude Code | a `Read(<pattern>)` entry in `permissions.deny` or `permissions.ask` of a project-scope settings file whose pattern covers `.env` or `.env.local`, or a bare `Read` (equally `Read(*)`) or a tool-name glob such as `*` there, which removes the Read tool. Patterns follow Claude's gitignore syntax and anchors: `**` spans directories, `*` and `?` stay within one path segment, a bare filename matches at any depth, `/` anchors at the settings source (the repository root for project settings), `//` at the filesystem root and `~/` at the home directory. So `Read(.env)`, `Read(**/.env)`, `Read(/.env)`, `Read(//**/.env)` and `Read(~/**/.env)` protect; `Read(config/**)` does not, and neither does a pattern anchored at one machine's path such as `Read(//home/alice/repo/.env)`, which protects only that clone | `No deny/ask rule protects .env files; add "Read(**/.env)" and "Read(**/.env.*)" to permissions.deny in .claude/settings.json.` |
| Cursor | a non-empty `hooks.beforeReadFile` list in `.cursor/hooks.json`; the hook body is not inspectable, so presence is the proxy | `No beforeReadFile hook guards secret files; add one to .cursor/hooks.json that blocks .env reads.` |
| OpenCode | OpenCode asks before reading `*.env` and `*.env.*` by default, evaluates its rules in order with the last matching rule winning (`ask` when none matches), and applies the rules in `opencode.json` after those defaults. The finding fires when the last rule matching `.env` or `.env.local` is `allow`: `"permission": "allow"`, `{"*": "allow"}`, `{"read": "allow"}`, `{"read": {"*": "allow"}}` or `{"read": {"*.env": "allow"}}`. In an OpenCode pattern `*` matches any characters, `/` included, `?` matches one, and nothing else is special, so `**/.env` reaches only a nested `.env`, never the root file | `permission allows .env reads, overriding OpenCode's default ask; remove the allow or add "*.env": "deny" and "*.env.*": "deny" after it under permission.read in opencode.json.` |

Only project-scope files count as protection. A deny in `settings.local.json`, in a user-scope file or in org-managed settings protects one machine; the repository itself carries no portable rule, which is what this finding is about.

## Why it matters

An agent that can read `.env` will read it when a task looks like it needs a variable, and the value lands in the conversation, the transcript and possibly a tool call. A deny in shared config travels with every clone.

## Example

```text
warning
  GM002  (cursor)  No beforeReadFile hook guards secret files; add one to .cursor/hooks.json that blocks .env reads.
```

## How to fix

Claude Code, in `.claude/settings.json`:

```json
{
  "permissions": {
    "deny": ["Read(**/.env)", "Read(**/.env.*)"]
  }
}
```

Cursor: add a `beforeReadFile` hook to `.cursor/hooks.json` that rejects secret paths. OpenCode: remove the `permission` allow that covers `.env`, or add `"*.env": "deny"` and `"*.env.*": "deny"` after it under `permission.read`; the last matching rule wins.

## What it does not report

- **Copilot / VS Code** has no hard deny (auto-approve is a boolean, not a path rule); **Codex** `sandbox_mode` and **Antigravity** denied commands are command and sandbox controls, not path-level read denies. None of them is judged here.
- **Agents present only on one machine.** User-scope files and the org-managed presence probes (both read only with `--user`) never make an agent present, so a repository with no Claude config gets no Claude Code warning even on a machine with org-managed Claude settings.
- **Presence is still broad within the repository.** An agent counts as present when any project- or local-scope artifact it reads is in the inventory. Cursor reads a root `AGENTS.md`, so a repository with only an `AGENTS.md` and no Cursor users still gets the Cursor advice. Narrowing presence to agent-distinctive artifacts is an open maintainer decision.
- **Claude rules anchored at one machine.** `Read(//home/alice/repo/.env)` or `Read(~/.env)` protects one clone, so it does not count; `Read(//**/.env)` or an unanchored pattern covers every clone. A `!` carve-out is ignored.
- **OpenCode agent permissions.** Rules in an agent's Markdown frontmatter take precedence over `opencode.json` in OpenCode; doctor reads only `opencode.json`.
- **Cursor's `.cursor/cli.json`.** Cursor's CLI documents a `permissions.deny` list there, with `Read(.env*)` as its example. Doctor does not inventory that file yet, pending confirmation that it binds the IDE agent as well as the CLI ([#488](https://github.com/LF-Decentralized-Trust-labs/gitmesh/issues/488)).
