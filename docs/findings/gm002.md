| **Applies to** | `claude-code`, `cursor` and `opencode`; project-scope `settings`, `hooks` and `config` files |
| **Message shape** | one finding per unprotected agent, naming the adapter and the file to edit |

## What it checks

GM002 is an absence rule. For each of the three agents whose committed configuration can express a path-level read protection, it fires once when that agent is present in the inventory and no committed rule protects `.env` or `.env.local`:

| Agent | Counts as protection | Message |
|---|---|---|
| Claude Code | a `Read(<glob>)` entry in `permissions.deny` or `permissions.ask` of a committed settings file whose glob matches `.env` or `.env.local` under Claude's own glob semantics: `Read(**)` and `Read(**/.env)` protect, `Read(config/**)` does not | `No deny/ask rule protects .env files; add "Read(**/.env)" and "Read(**/.env.*)" to permissions.deny in .claude/settings.json.` |
| Cursor | a non-empty `hooks.beforeReadFile` list in `.cursor/hooks.json`; the hook body is not inspectable, so presence is the best available proxy | `No beforeReadFile hook guards secret files; add one to .cursor/hooks.json that blocks .env reads.` |
| OpenCode | OpenCode denies `*.env` and `*.env.*` reads by default, so it is unprotected only when `permission.read` in `opencode.json` makes a secret path resolve to `"allow"` (last matching rule wins) | `permission.read allows .env files, overriding OpenCode's default deny; remove the allow or set "*.env" and "*.env.*" back to "deny" in opencode.json.` |

Only project-scope files count. A deny in `settings.local.json`, in a user-scope file or in org-managed settings protects one machine; the repository itself carries no portable rule, which is what this finding is about.

## Why it matters

An agent that can read `.env` will read it when a task looks like it needs a variable, and the value lands in the conversation, the transcript and possibly a tool call. A committed deny travels with every clone.

## Example

```text
warning
  GM002  (cursor)  No beforeReadFile hook guards secret files; add one to .cursor/hooks.json that blocks .env reads.
```

## How to fix

Claude Code, in `.claude/settings.json`:

```json
{
  "permissions": {
    "deny": ["Read(**/.env)", "Read(**/.env.*)"]
  }
}
```

Cursor: add a `beforeReadFile` hook to `.cursor/hooks.json` that rejects secret paths. OpenCode: remove the `permission.read` allow that covers `.env`, or set `"*.env"` and `"*.env.*"` back to `"deny"` in `opencode.json`.

## What it does not report

- **Copilot / VS Code** has no hard deny (auto-approve is a boolean, not a path rule); **Codex** `sandbox_mode` and **Antigravity** denied commands are command and sandbox controls, not path-level read denies. None of them is judged here.
- **Presence is broad.** An agent counts as present when any artifact it reads is in the inventory. Cursor reads a root `AGENTS.md`, so a repository with only an `AGENTS.md` and no Cursor users still gets the Cursor advice. Narrowing presence to agent-distinctive artifacts is an open maintainer decision.
- The OpenCode check assumes a user's `permission.read` object overrides the default keys in place; the OpenCode docs do not state the merge rule (verified 2026-08-29).
