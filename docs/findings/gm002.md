## What it checks

GM002 is an absence rule. For each of the three agents whose shared configuration can express a path-level read protection, it fires once when that agent is present in the inventory and no project-scope rule protects `.env` or `.env.local` (a rule covering either one counts):

| Agent | Counts as protection | Message |
|---|---|---|
| Claude Code | a `Read(<glob>)` entry in `permissions.deny` or `permissions.ask` of a project-scope settings file whose glob matches `.env` or `.env.local`. The matcher is minimal: `**` spans directories, `*` and `?` stay within one path segment, and a leading `./` is ignored, so `Read(**)` and `Read(**/.env)` protect and `Read(config/**)` does not. Claude's anchored forms (`Read(/.env)`, `Read(//**/.env)`) and a bare `Read` rule are not recognized yet and still get the warning | `No deny/ask rule protects .env files; add "Read(**/.env)" and "Read(**/.env.*)" to permissions.deny in .claude/settings.json.` |
| Cursor | a non-empty `hooks.beforeReadFile` list in `.cursor/hooks.json`; the hook body is not inspectable, so presence is the proxy | `No beforeReadFile hook guards secret files; add one to .cursor/hooks.json that blocks .env reads.` |
| OpenCode | OpenCode protects `*.env` and `*.env.*` by default (current releases ask before reading them), so the rule fires only when `permission.read` in `opencode.json` sets a secret path to `"allow"` | `permission.read allows .env files, overriding OpenCode's default deny; remove the allow or set "*.env" and "*.env.*" back to "deny" in opencode.json.` |

Only project-scope files count as protection. A deny in `settings.local.json`, in a user-scope file or in org-managed settings protects one machine; the repository itself carries no portable rule, which is what this finding is about.

## Why it matters

An agent that can read `.env` will read it when a task looks like it needs a variable, and the value lands in the conversation, the transcript and possibly a tool call. A deny in shared config travels with every clone.

## Example

```text
warning
  GM002  (cursor)  No beforeReadFile hook guards secret files; add one to .cursor/hooks.json that blocks .env reads.
```

## How to fix

Claude Code, in `.claude/settings.json`:

```json
{
  "permissions": {
    "deny": ["Read(**/.env)", "Read(**/.env.*)"]
  }
}
```

Cursor: add a `beforeReadFile` hook to `.cursor/hooks.json` that rejects secret paths. OpenCode: remove the `permission.read` allow that covers `.env`, which also clears the finding.

## What it does not report

- **Copilot / VS Code** has no hard deny (auto-approve is a boolean, not a path rule); **Codex** `sandbox_mode` and **Antigravity** denied commands are command and sandbox controls, not path-level read denies. None of them is judged here.
- **Presence is broad.** An agent counts as present when any artifact it reads is in the inventory, in any scope. Cursor reads a root `AGENTS.md`, so a repository with only an `AGENTS.md` and no Cursor users still gets the Cursor advice. The machine-level probes doctor runs without `--user` count too: on a machine with org-managed Claude settings, a repository with no Claude config gets the Claude Code warning. Narrowing presence to agent-distinctive artifacts is an open maintainer decision.
- **Broader OpenCode allows.** OpenCode appends a user's `permission` rules after its own defaults and applies the last match, so `"permission": "allow"`, `{"*": "allow"}` or `{"read": {"*": "allow"}}` also expose `.env`. GM002 treats user keys as overriding the defaults in place and does not report these forms yet. The reverse also happens: an allow under another pattern (such as `"**"`) followed by `"*.env": "deny"` is protected in OpenCode but still reported.
