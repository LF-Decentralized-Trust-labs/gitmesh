## What it checks

GM001 scans each configuration file line by line for two kinds of evidence:

1. **Vendor token shapes**, matched anywhere on a line, including bare `args` entries and URLs: private-key PEM headers, GitHub (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`), GitLab (`glpat-`), OpenAI/Anthropic-style (`sk-`), Stripe (`sk_live_`, `rk_test_`, ...), Slack (`xoxb-`, `xoxp-`, ...), AWS access key ids (`AKIA`, `ASIA`), Google API keys (`AIza`), npm (`npm_`), Hugging Face (`hf_`), JWTs, and credentials embedded in URLs (`scheme://user:password@host`).
2. **High-entropy values under credential-named keys**: a quoted value at least 16 characters long, token alphabet only, mixing letters and digits, with Shannon entropy of 3.5 bits per character or more, sitting under a key or CLI flag whose name contains `token`, `secret`, `password`, `api_key`, `credential`, `private_key`, `authorization` or `bearer`. An auth scheme prefix (`Bearer …`, `Basic …`, `Token …`) is stripped before the test. The two-entry `"--api-key", "value"` form and the `--token=value` form both count in double-quoted strings; single-quoted TOML strings are not matched.

The scanner reads lines, not parsed trees, so the same code covers `.mcp.json`, `.claude/settings.json`, `.codex/config.toml`, `opencode.jsonc`, `.gemini/settings.json`, `.cursor/mcp.json`, `.vscode/mcp.json` and `.cursor/hooks.json` without a parser and cannot fail on malformed input.

## Why it matters

If the file is committed, the token ships to every clone, every fork and every CI log that prints the file: treat the value as leaked. GM001 also scans local-scope files that are normally gitignored (`.claude/settings.local.json`, `.agents/local.json`) and, with `--user`, user-scope config. There a finding means the value sits in plaintext on this machine, not that it was committed; doctor does not read git status in this release, so it cannot tell the two apart.

## Example

```text
error
  GM001  .mcp.json  Plaintext GitHub token in "GITHUB_TOKEN" (line 6); move it out of the file and reference it from the environment.
```

A GM001 finding never prints the value itself, in any output mode.

## How to fix

Replace the literal with an environment reference and provide the value outside the repository. In Claude Code's `.mcp.json`, `${VAR}` is expanded from your environment when the server starts:

```json
{
  "mcpServers": {
    "github": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "-e", "GITHUB_PERSONAL_ACCESS_TOKEN", "ghcr.io/github/github-mcp-server"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PERSONAL_ACCESS_TOKEN}" }
    }
  }
}
```

Other tools spell references differently: Cursor uses `${env:VAR}`, OpenCode `{env:VAR}`, and VS Code prompts with `${input:…}` or loads an `envFile`. Use each tool's own syntax: a reference the tool does not expand reaches the server as literal text. Then rotate the exposed token.

A credential embedded in a URL is reported even when its password part is a reference (`https://bot:${TOKEN}@host`), because the URL pattern has no placeholder exemption; move the whole URL into one environment variable instead.

## What it does not report

- **Placeholders and references, in the high-entropy check only.** A value under a credential-named key is skipped when it starts with `$`, `%`, `{{`, `<`, `op://`, `env:`, `/`, `./`, `~`, `http://`, `https://`, `changeme`, `change-me`, `your-`, `your_`, `placeholder`, `example`, `dummy`, `xxx`, `***` or `...`. These are prefix matches: a value with `example` in the middle, or a relative path such as `config/sa.json`, can still fire. Vendor token shapes have no such exemption, so a placeholder like `ghp_xxxx…` or `sk-your-key-here` is reported.
- **Instruction-file prose.** `AGENTS.md`, `CLAUDE.md`, rules and skills are not scanned: a documentation example would produce false positives. cc-health-check and gitleaks cover prose.
- **Third-party-manager source files.** `.agents/agents.json` and the Markdown sources under `.ruler/` and `.rulesync/` are inventoried as sources, not config, and are not scanned yet.
- **`.env` files.** They are never inventoried, so example values there are never scanned. Whether an `.env` file is committed is generic repository hygiene (gitleaks, AgentLint S1).
- **Unquoted YAML values** reach only the token-shape patterns; the entropy check needs a quoted `key: "value"` pair.

One hit is reported per line and key; the first matching reason wins. There is no allowlist in this release, so an accepted finding cannot be suppressed.
