## What it checks

GM001 scans each configuration file line by line for two kinds of evidence:

1. **Vendor token shapes**, matched anywhere on a line, including bare `args` entries and URLs: private-key PEM headers, GitHub (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`), GitLab (`glpat-`), OpenAI/Anthropic-style (`sk-`), Stripe (`sk_live_`, `rk_test_`, ...), Slack (`xoxb-`, `xoxp-`, ...), AWS access key ids (`AKIA`, `ASIA`), Google API keys (`AIza`), npm (`npm_`), Hugging Face (`hf_`), JWTs, and credentials embedded in URLs (`scheme://user:password@host`).
2. **High-entropy values under credential-named keys**: a quoted value at least 16 characters long, token alphabet only, mixing letters and digits, with Shannon entropy of 3.5 bits per character or more, sitting under a key or CLI flag whose name contains `token`, `secret`, `password`, `api_key`, `credential`, `private_key`, `authorization` or `bearer`. An auth scheme prefix (`Bearer …`, `Basic …`, `Token …`) is stripped before the test. The two-entry `"--api-key", "value"` form and the `--token=value` form both count.

The scanner reads lines, not parsed trees, so the same code covers `.mcp.json`, `.claude/settings.json`, `.codex/config.toml`, `opencode.jsonc`, `.gemini/settings.json`, `.cursor/mcp.json`, `.vscode/mcp.json` and `.cursor/hooks.json` without a parser and cannot fail on malformed input.

## Why it matters

A token in a committed config file ships to every clone, every fork and every CI log that prints the file. Once committed, treat the value as leaked.

## Example

```text
error
  GM001  .mcp.json  Plaintext GitHub token in "GITHUB_TOKEN" (line 6); move it out of the file and reference it from the environment.
```

The value itself is never printed, in any output mode.

## How to fix

Replace the literal with an environment reference and provide the value outside the repository:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}
```

Then rotate the exposed token.

## What it does not report

- **Placeholders and references.** Values starting with `$`, `%`, `{{`, `<`, `op://`, `env:`, a path (`/`, `./`, `~`), `http://` or `https://`, or with `changeme`, `your-`, `placeholder`, `example`, `dummy`, `xxx`, `***` or `...` are skipped by the entropy check.
- **Instruction-file prose.** `AGENTS.md`, `CLAUDE.md`, rules and skills are not scanned: a documentation example would produce false positives. cc-health-check and gitleaks cover prose; see the [benchmark checklist](/comparisons).
- **`.env` files.** They are never inventoried, so example values there are never scanned. Whether an `.env` file is committed is generic repository hygiene (gitleaks, AgentLint S1).
- **Unquoted YAML values** reach only the token-shape patterns; the entropy check needs a quoted `key: "value"` pair.

One hit is reported per line and key; the first matching reason wins. There is no allowlist in this release, so an accepted finding cannot be suppressed.
