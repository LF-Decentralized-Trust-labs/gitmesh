| | |
|---|---|
| **Severity** | info (no score cost; never fails the run at the default `--fail-on warning`) |
| **Applies to** | project- and local-scope artifacts of every adapter except `third-party-managers` |
| **Message shape** | `Configuration for <adapter> is present in the repository, but <adapter> is unseen in its history; if the team has moved on from this agent, retire the orphan config.` |
| **Status** | implemented and tested, **silent in this release** (see below) |

## What it checks

Once per adapter: the adapter has at least one *distinctive* project- or local-scope artifact in the inventory, and the repository's history shows no evidence of that agent. Distinctive means a path claimed by that adapter alone. A shared root `AGENTS.md`, which eight adapters claim, is evidence for none of them specifically and never makes an adapter present here; without that gate every `AGENTS.md` repository would fan out one orphan finding per reader.

## Why it matters

An orphan costs review attention, misleads newcomers about what the team actually uses, and keeps a surface alive that nobody audits. It harms nothing at runtime, which is why it is informational.

## Why it is silent today

The rule engine is pure: it never touches git. History evidence has to be supplied by the doctor pipeline, and computing it needs a git reader that keeps doctor free of subprocesses, which this release does not have. Doctor never treats missing evidence as evidence of orphanhood, so GM008 reports nothing until that reader lands. The evidence standard (what counts as "seen in history") will be a recorded maintainer decision when it does.

Until then, Claude Code's `/doctor` reports unused skills, MCP servers and plugins for Claude from local transcripts.

## How to fix

If the team no longer uses the agent, delete the files only that agent reads; if it does, keep them. The finding is informational and never fails the default run.

## What it does not report

- User-scope and org-managed artifacts: machine state, not repository configuration.
- Third-party-manager artifacts: a manager is not an agent, and management is never itself a finding (ADR-004).
