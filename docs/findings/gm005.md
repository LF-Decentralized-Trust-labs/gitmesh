| **Applies to** | project- and local-scope `mcp-config`, `config` and `settings` artifacts of `antigravity`, `claude-code`, `codex`, `copilot`, `cursor`, `opencode` and `roo`, plus Ruler's `.ruler/mcp.json` and rulesync's `.rulesync/mcp.json(c)` |
| **Message shape** | names the server, the field or key, and the files; never a value or a url |

## What it checks

Doctor collects every MCP server definition it can read:

| Shape | Files |
|---|---|
| an `mcpServers` object | `.mcp.json` (Claude Code), `.cursor/mcp.json`, `.roo/mcp.json`, Antigravity `mcp_config.json` under `.gemini/` and `.gemini/settings.json`, `.ruler/mcp.json`, `.rulesync/mcp.json` and `.jsonc` |
| a `servers` object in an `mcp-config` artifact | `.vscode/mcp.json` (Copilot) |
| an `mcp` object | `opencode.json` and `opencode.jsonc` (entries carry `environment` rather than `env`) |
| `[mcp_servers.<name>]` tables | `.codex/config.toml`, including inline and sub-table `env` and `http_headers` |

Definitions with the same server name are compared across *different* adapters only. Two things are compared: the `url` key, and every env or header key both tools set (`env` in one tool against `environment` in another, `headers` against `http_headers`). Values are compared as written: doctor does not expand or normalize environment references, so `${GITHUB_TOKEN}` in `.mcp.json` and `${env:GITHUB_TOKEN}` in `.cursor/mcp.json` count as different values. A key present in one tool and absent in the other is silent, because wiring legitimately differs per tool. Two different literal values for the same key cannot both be current, so that fires.

## Why it matters

When `github` points at one endpoint in `.mcp.json` and another in `.cursor/mcp.json`, or the same env key carries two values, at least one agent runs against a stale endpoint or credential. Nothing inside a single tool can see this; it is the cross-tool rot doctor exists to surface.

## Example

```text
warning
  GM005  MCP server "github" is configured with different values for env "GITHUB_TOKEN" across tools (.cursor/mcp.json, .mcp.json); one of them is stale - settle on one credential and reference it from the environment.
```

The url form reads: `MCP server "<name>" is defined with different urls across tools (<files>); point every tool at the same endpoint or remove the stale definition.` Urls are not printed either, because a url can embed credentials.

## How to fix

Pick the current definition and point every tool's file at the same endpoint. Keep the credential out of the files by referencing it in each tool's own syntax: `${VAR}` in Claude Code's `.mcp.json`, `${env:VAR}` in Cursor, `{env:VAR}` in OpenCode, an `${input:…}` prompt or an `envFile` in VS Code. A reference a tool does not expand reaches the server as literal text, so do not copy one tool's spelling into another's file.

GM005 compares those references as written, so tools that spell the same variable differently are still reported. In this release that finding is a known false positive, and it cannot be suppressed. If a third-party manager generated one of the files, re-run that manager: the finding reports the drift and suggests nothing destructive in the manager's territory.

## What it does not report

- **Same-adapter layering.** A root `.mcp.json` versus a nested one is that tool's own precedence, not cross-tool drift.
- **User and managed tiers**, which layer per machine over the repository.
- **Third-party-manager files other than `mcp.json` and `mcp.jsonc`**: the `[mcp_servers]` tables in `ruler.toml`, `.agents/agents.json`, `agentsync.json`, ...
- **Endpoint keys other than `url`**, such as Antigravity's `serverUrl` or Gemini's `httpUrl`.
- **Keys set in only one tool.**
