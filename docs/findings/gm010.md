|---|---|
| **Severity** | warning (5 score points; fails the run at the default `--fail-on warning`) |
| **Applies to** | project-scope `instructions` artifacts at the repository root: exactly `CLAUDE.md` and `AGENTS.md` |
| **Message shape** | one of two messages, below |

## What it checks

`AGENTS.md` is the cross-tool instruction file: Codex, Cursor, Copilot, OpenCode, Devin, Cline, Roo and others read it. Claude Code reads `CLAUDE.md`. Since v2.1.277 (2026-09-18) it also reads `AGENTS.md`, but only in a project that has no `CLAUDE.md`; when both exist it reads `CLAUDE.md` alone by default. Earlier versions do not read `AGENTS.md` at all, the gap tracked as anthropics/claude-code#6235 (closed as completed on 2026-08-17). The bridge that works on every version is an `@AGENTS.md` import line inside `CLAUDE.md`, or a symlink. GM010 reports the two shapes where a `CLAUDE.md` is not joined to `AGENTS.md`:

| Situation | Message |
|---|---|
| `CLAUDE.md` present, no root `AGENTS.md` | `CLAUDE.md is present but there is no AGENTS.md for the other agents to read; move the shared instructions to AGENTS.md and keep CLAUDE.md as an "@AGENTS.md" shim.` |
| both present, neither bridged | `CLAUDE.md does not bridge to AGENTS.md; add an "@AGENTS.md" import line to CLAUDE.md (or symlink one file to the other) so both stay one instruction source.` |

A repository with `AGENTS.md` and no root `CLAUDE.md` gets no GM010 finding: Claude Code v2.1.277 and later reads that `AGENTS.md` directly. Contributors on older Claude Code versions still need a shim to see it.

Bridged means `CLAUDE.md` contains an `@AGENTS.md` or `@./AGENTS.md` token on a line, or either file is a symlink whose link target is literally the other file's name, optionally prefixed with `./`. An absolute or `../` link target is not recognized as a bridge in this release, although the drift report shows such a pair as a zero-drift symlink group.

## Why it matters

Two hand-maintained copies drift. The cross-tool drift report on the same run shows how far; GM010 names the fix.

## Example

```text
warning
  GM010  CLAUDE.md  CLAUDE.md does not bridge to AGENTS.md; add an "@AGENTS.md" import line to CLAUDE.md (or symlink one file to the other) so both stay one instruction source.
```

## How to fix

Keep the shared instructions in `AGENTS.md` and make `CLAUDE.md` a shim that imports them plus anything Claude-only:

```markdown
@AGENTS.md

- Claude-only: prefer the Edit tool over shell edits.
```

Doctor recognizes the shim: a bridged `CLAUDE.md` is excluded from the drift comparison, so adopting this fix never costs drift points. A relative symlink (`ln -s AGENTS.md CLAUDE.md`) works too and shows in the report as a zero-drift symlink group. GitMesh's own repository uses the import form.

Anthropic's memory documentation says a `CLAUDE.md` that holds nothing but `@AGENTS.md` can be removed on v2.1.277 and later. GM010 stays silent after you remove it; keep the shim if contributors use older Claude Code versions or you have Claude-only instructions to add.

## What it does not report

- **Nested pairs** (`packages/app/CLAUDE.md` beside `packages/app/AGENTS.md`) are not compared in this release: GM010 looks only at the repository root, and the drift report compares root documents only.
- **`GEMINI.md`.** Antigravity's file will get the same shim from the planned emitter, but this finding is scoped to the `CLAUDE.md` and `AGENTS.md` pair.
- **Ambiguous bridges.** The import scan is a lenient line match: a shim shown inside a fenced example counts as a bridge, and a `CLAUDE.md` that disappears during the run is treated as bridged. Erring silent beats nagging a repository that already joined the two files. A `CLAUDE.md` doctor may not read aborts the run with exit `2` instead.
- **`AGENTS.md` without a `CLAUDE.md`.** Current Claude Code reads it, so there is nothing to bridge.
- Broken symlinks on either side are ignored.

Claude Code's AGENTS.md support changed in v2.1.277; this page describes the rule as it behaves in this release.
