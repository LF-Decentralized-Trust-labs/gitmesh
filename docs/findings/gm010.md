## What it checks

`AGENTS.md` is the cross-tool instruction file: Codex, Cursor, Copilot, OpenCode, Devin, Cline, Roo and others read it. Claude Code does not read it natively (anthropics/claude-code#6235, the tracker's largest unmet request as of the 2026-07-19 research this rule is based on). The documented workarounds are an `@AGENTS.md` import line inside `CLAUDE.md`, or a symlink. GM010 reports the three shapes where the two files are not one source:

| Situation | Message |
|---|---|
| `AGENTS.md` present, no root `CLAUDE.md` | `AGENTS.md is present but Claude Code does not read it natively (anthropics/claude-code#6235); add a CLAUDE.md shim with an "@AGENTS.md" import line so Claude users see the shared instructions.` |
| `CLAUDE.md` present, no root `AGENTS.md` | `CLAUDE.md is present but there is no AGENTS.md for the other agents to read; move the shared instructions to AGENTS.md and keep CLAUDE.md as an "@AGENTS.md" shim (the #6235 workaround).` |
| both present, neither bridged | `CLAUDE.md does not bridge to AGENTS.md; add an "@AGENTS.md" import line to CLAUDE.md (or symlink one file to the other) so both stay one instruction source.` |

Bridged means `CLAUDE.md` contains an `@AGENTS.md` or `@./AGENTS.md` token on a line, or either file is a symlink to the other.

## Why it matters

Two hand-maintained copies drift. The cross-tool drift report on the same run shows how far; GM010 names the fix.

## Example

```text
warning
  GM010  CLAUDE.md  CLAUDE.md does not bridge to AGENTS.md; add an "@AGENTS.md" import line to CLAUDE.md (or symlink one file to the other) so both stay one instruction source.
```

## How to fix

Keep the shared instructions in `AGENTS.md` and make `CLAUDE.md` a shim that imports them plus anything Claude-only:

```markdown
@AGENTS.md

- Claude-only: prefer the Edit tool over shell edits.
```

Doctor recognizes the shim: a bridged `CLAUDE.md` is excluded from the drift comparison, so adopting this fix never costs drift points. A symlink (`ln -s AGENTS.md CLAUDE.md`) works too and shows in the report as a zero-drift symlink group. GitMesh's own repository uses the import form.

## What it does not report

- **Nested pairs** (`packages/app/CLAUDE.md` beside `packages/app/AGENTS.md`): per-directory context, whose divergence is the drift report's job.
- **`GEMINI.md`.** Antigravity's file will get the same shim from the planned emitter, but this finding is scoped to the `CLAUDE.md` and `AGENTS.md` pair.
- **Ambiguous bridges.** The import scan is a lenient line match: a shim shown inside a fenced example counts as a bridge, and a `CLAUDE.md` whose content could not be read is treated as bridged. Erring silent beats nagging a repository that already solved #6235.
- Broken symlinks on either side are ignored.

If Claude Code's AGENTS.md status changes, this rule and this page change with it.
