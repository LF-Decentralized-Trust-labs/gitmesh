| | |
|---|---|
| **Severity** | warning (5 score points; fails the run at the default `--fail-on warning`) |
| **Applies to** | project- and local-scope artifacts of every adapter, third-party managers included |
| **Message shape** | `<file> is a personal local-scope file but is committed; gitignore it so personal machine state stays out of the shared repository.` or `<file> is shared project configuration but is gitignored; commit it, or move the personal parts to a local-scope variant.` |
| **Status** | implemented and tested, **silent in this release** (see below) |

## What it checks

Every agent family splits personal from shared configuration: `CLAUDE.local.md` and `.claude/settings.local.json` beside their project twins, `rulesync.local.jsonc`, `.agents/local.json`. The split only works when git agrees. The rule fires on explicit evidence only:

- a **local-scope** artifact that is **tracked** (committed): one person's machine state, and possibly their personal paths or hook commands, ships to every clone;
- a **project-scope** artifact that is **ignored and untracked**: configuration that looks shared is invisible to teammates and CI.

A tracked-but-ignored project file (gitignore drift over an already committed file) sends mixed signals rather than either clear failure and stays out.

## Why it matters

A committed `settings.local.json` can carry permission grants, hook commands or absolute paths from one laptop into everyone's checkout. A gitignored `.cursor/rules/` means the rules a reviewer sees are not the rules CI's agent runs with. Both are hygiene with leak-adjacent consequences and no active bypass, hence warning.

## Why it is silent today

The rule engine never touches git. Per-file tracked and ignored status has to be supplied by the doctor pipeline, which needs a git reader that keeps doctor free of subprocesses; this release does not have one, and the rule fires only on explicit values, never on "unknown". AgentLint's C5 check (`CLAUDE.local.md` not tracked) covers the most common case today.

## How to fix

Gitignore the local file and stop tracking it (`git rm --cached <file>`), or commit the shared one and move anything personal into its local-scope variant. For a third-party manager's local file, the fix is a `.gitignore` line.

## What it does not report

- User-scope and org-managed artifacts, which live outside the repository where git status has no meaning.
- Anything that requires writing into a third-party manager's territory. The remediation for a manager's local file is a `.gitignore` line, never an edit to the manager's files (ADR-004).
