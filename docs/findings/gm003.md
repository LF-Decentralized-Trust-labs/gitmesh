| | |
|---|---|
| **Severity** | error (20 score points; fails the run at the default `--fail-on warning`) |
| **Applies to** | `claude-code`, `codex` and `copilot`; project-scope `settings` and `config` files |
| **Message shape** | names the file and the key; never prints pattern values |

## What it checks

An exact key/value match that turns off an agent's own approval or sandbox guardrail in a project-scope file, the layer a repository normally commits:

| Agent | File | Fires on |
|---|---|---|
| Claude Code | project settings (`.claude/settings.json`) | `permissions.defaultMode` set to `"bypassPermissions"` (ignored by Claude Code v2.1.257 and later; see below) |
| Codex | `.codex/config.toml`, root-table lines only | `sandbox_mode = "danger-full-access"` or `approval_policy = "never"` |
| Copilot / VS Code | `.vscode/settings.json` | `chat.tools.global.autoApprove`, `chat.tools.terminal.autoApprove` or `chat.tools.urls.autoApprove` set to `true`, or to an object with a `true` value at its top level (`{"npm test": true}`); object-valued entries such as `{"approve": true}` are not inspected yet |

Codex modes inside a `[profiles.x]` table do not fire. The Codex check is a tolerant line scan, so a malformed TOML file never aborts the run.

## Why it matters

Unlike [GM002](/findings/gm002), which reports missing protection, this is an active switch. Once committed, it binds every clone: a contributor who opens the repository gets an agent that no longer asks before running commands or editing files, and CI gets the same. Codex reads a project's `config.toml` only once the project is trusted, so the switch arms the moment someone trusts it.

Claude Code v2.1.257 (2026-09-01) and later ignore `bypassPermissions` in `.claude/settings.json` and `.claude/settings.local.json`; the mode now takes effect only from user or managed settings or `--permission-mode`. A committed one still binds contributors on older versions, which is why GM003 still reports it.

## Example

```text
error
  GM003  .claude/settings.json  permissions.defaultMode is "bypassPermissions" in .claude/settings.json, disabling permission prompts for everyone using this repo; remove it or use "acceptEdits".
```

The other messages:

- `sandbox_mode = "danger-full-access" in .codex/config.toml removes the Codex kernel sandbox once the project is trusted; use "workspace-write" or "read-only".`
- `approval_policy = "never" in .codex/config.toml auto-approves every Codex action; use "on-request" or "untrusted".`
- `chat.tools.terminal.autoApprove is enabled in .vscode/settings.json, auto-approving Copilot tool use; remove the key or set it to false.`

Do not pick `"untrusted"` from the second message: Codex retired that value in August 2026, and current releases refuse to load a config that sets it. Use `"on-request"`.

## How to fix

Remove the key, or replace it with a conservative setting: `"acceptEdits"` (or no `defaultMode`) for Claude Code, `"workspace-write"` or `"read-only"` for `sandbox_mode`, `"on-request"` for `approval_policy`. For the VS Code terminal and URL keys, which hold objects, remove the key or its `true` entries rather than setting it to `false`.

If one developer wants the mode for themselves, it belongs outside the repository: Claude Code user settings (`~/.claude/settings.json`) or `--permission-mode` for a single session, `~/.codex/config.toml`, or VS Code user settings. This rule never reads those. Moving the key to `.claude/settings.local.json` clears the finding but no longer enables the mode on current Claude Code.

## What it does not report

- **Local, user and managed scopes.** `settings.local.json` is gitignored by convention (whether it is actually committed is [GM009](/findings/gm009)'s question, silent in this release), user scope is personal machine state, and org-managed settings are the organization's deliberate channel.
- **Cursor** exposes no committed auto-run mode switch: its committed hooks add checks rather than remove them, and its rules are instructions. **OpenCode** `permission` entries are per-pattern grants, not a mode switch (a blanket read allow is [GM002](/findings/gm002)'s territory). **Antigravity**'s enforcement lives in user-scope `antigravity-cli` settings, inventoried only as a content-less probe. **Devin/Windsurf, Cline and Roo** expose no approval-mode surface doctor can read.
- **Blanket allow patterns** such as `Bash(*)` or `mcp__*` in Claude Code's `permissions.allow` are not flagged in this release; AgentLint H4 covers them. Explicit `false` values and all-false objects in VS Code are protective and silent.
