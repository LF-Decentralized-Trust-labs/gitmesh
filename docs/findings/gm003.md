| | |
|---|---|
| **Severity** | error (20 score points; fails the run at the default `--fail-on warning`) |
| **Applies to** | `claude-code`, `codex` and `copilot`; project-scope `settings` and `config` files |
| **Message shape** | names the file and the key; never prints pattern values |

## What it checks

An exact key/value match that turns off an agent's own approval or sandbox guardrail in a file committed to the repository:

| Agent | File | Fires on |
|---|---|---|
| Claude Code | committed settings (`.claude/settings.json`) | `permissions.defaultMode` set to `"bypassPermissions"` |
| Codex | `.codex/config.toml`, root-table lines only | `sandbox_mode = "danger-full-access"` or `approval_policy = "never"` |
| Copilot / VS Code | `.vscode/settings.json` | `chat.tools.global.autoApprove`, `chat.tools.terminal.autoApprove` or `chat.tools.urls.autoApprove` set to `true`, or to an object containing a `true` value |

Codex modes inside a `[profiles.x]` table are inert until that profile is selected and do not fire. The Codex check is a tolerant line scan, so a malformed TOML file never aborts the run.

## Why it matters

Unlike [GM002](/findings/gm002), which reports missing protection, this is an active switch. Committed, it binds every clone: a contributor who opens the repository gets an agent that no longer asks before running commands or editing files, and CI gets the same. Codex reads a project's `config.toml` only once the project is trusted, so the switch arms the moment someone trusts it.

## Example

```text
error
  GM003  .claude/settings.json  permissions.defaultMode is "bypassPermissions" in .claude/settings.json, disabling permission prompts for everyone using this repo; remove it or use "acceptEdits".
```

The other messages:

- `sandbox_mode = "danger-full-access" in .codex/config.toml removes the Codex kernel sandbox once the project is trusted; use "workspace-write" or "read-only".`
- `approval_policy = "never" in .codex/config.toml auto-approves every Codex action; use "on-request" or "untrusted".`
- `chat.tools.terminal.autoApprove is enabled in .vscode/settings.json, auto-approving Copilot tool use; remove the key or set it to false.`

## How to fix

Remove the key, or replace it with the conservative setting named in the message. If one developer wants the mode locally, it belongs in the gitignored local layer (`.claude/settings.local.json`, `~/.codex/config.toml`, VS Code user settings), which this rule never reads.

## What it does not report

- **Local, user and managed scopes.** `settings.local.json` is gitignored by convention (its hygiene is [GM009](/findings/gm009)), user scope is personal machine state, and org-managed settings are the organization's deliberate channel.
- **Cursor** has no committed yolo/auto-run file: its committed surface (hooks, rules) only adds guardrails. **OpenCode** `permission` entries are per-pattern grants, not a mode switch (a blanket read allow is [GM002](/findings/gm002)). **Antigravity**'s enforcement lives in user-scope `antigravity-cli` settings, inventoried only as a content-less probe. **Devin/Windsurf, Cline and Roo** expose no approval-mode surface doctor can read.
- **Blanket allow patterns** such as `Bash(*)` or `mcp__*` in Claude Code's `permissions.allow` are not flagged in this release; AgentLint H4 covers them. Explicit `false` values and all-false objects in VS Code are protective and silent.
