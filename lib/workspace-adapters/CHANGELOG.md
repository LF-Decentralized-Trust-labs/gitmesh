- 6175bd2: Add the `copilot` adapter's `detect()` (pivot T1.4): a pure, read-only, symlink-aware inventory of the GitHub Copilot config surface - AGENTS.md at any depth, `.github/copilot-instructions.md`, `.github/instructions/**/*.instructions.md` (with parsed YAML frontmatter for `applyTo`), `.vscode/mcp.json`, `.github/agents/**/*.md` subagent definitions, and `.vscode/settings.json`, which reports which `chat.tools.*.autoApprove` keys are set and never any settings value. - 9e882b7: Add the `cursor` adapter's `detect()` (pivot T1.3): a pure, read-only, symlink-aware inventory of the Cursor config surface - AGENTS.md at any depth, legacy `.cursorrules`, `.cursor/rules/*.mdc` at the root and in nested `.cursor` directories (Cursor v0.50+ monorepo rules) with parsed YAML frontmatter (description, globs - block and flow lists normalized to Cursor's comma-separated form - and alwaysApply), `.cursor/mcp.json`, `.cursor/agents/` subagent definitions, and `.cursor/hooks.json` (v1.7+ hooks). - 408a125: Add the grouped T1.6 detectors (pivot §12): `opencode`, `agentsmd`, `devin` (ex-Windsurf) and `cline`/`roo`, each a pure, read-only, symlink-aware `detect()` with per-tool golden fixtures including a negative case, registered lazily in the built-in registry. Surfaces were re-verified against each vendor's docs on 2026-08-24 and are wider than the §4.3 rows: opencode gains `.opencode/` command/agent/mode/skill/plugin/theme trees (singular and plural directory names) and `opencode.json{,c}` at any depth; devin gains the preferred `.devin/rules/`, `.windsurf/{workflows,hooks.json,skills}`, and `.devin/blueprint.yaml` alongside the legacy `.windsurfrules`; cline classifies the `.clinerules` file-or-directory surface with its `workflows/` and `hooks/` subtrees; roo covers `.roo/rules*/` trees with `.roorules*` fallbacks, `.roomodes`, `.roo/mcp.json`, `.roo/commands/` and `.rooignore`. Adds the shared `collectDirFiles` single-level scan to `detect-fs`.
- a84df32: Add the second pair of risk rules to the GM table (pivot §8.1 item 3, T1.12). `GM003` (error) reports a bypass-permissions / auto-approve / danger-full-access mode in committed config: Claude Code `permissions.defaultMode: "bypassPermissions"` in a project settings file, Codex `sandbox_mode = "danger-full-access"` or `approval_policy = "never"` on a root-table line of `.codex/config.toml` (a mode inside `[profiles.x]` is inert until that profile is selected), and any of VS Code's three `chat.tools.*.autoApprove` keys set to `true` or to an object containing a `true` - findings name the file and key, never pattern values (the T1.4 rule), and only project scope counts (`settings.local.json` hygiene is GM009's lane); cursor (no committed yolo surface), opencode (granular per-pattern grants, not a mode switch - maintainer decision 2026-08-31), antigravity (user-scope surface) and devin are excluded with reasons in the rule doc. `GM004` (warning) reports a skill with executable content and no recognized pin: executable means the detectors' new `executable` stamp - `collectSkillManifests` and the opencode/antigravity skill walks now mark a manifest whose directory holds script files, the adapters' minor bump - or a SKILL.md body that opens a shell code fence or references a script file (`.js` tokens must be path-shaped so prose like "Node.js" never fires); a recognized pin is a key of `skills` in `skills-lock.json` (any version), of `servers` in `.mcp.lock`, or of `skills` in `.gitmesh/lock.json` (honored whenever the caller inventories it; no detector emits it until the T5.x lockfile lands), matching the key or its last `/`-segment for namespaced entries. Per ADR-004 a manager's lockfile presence is never itself a finding and `.ruler/skills/**` sources never enter the rule. `isRecord` moves next to `parseJsonc` in core's `jsonc.ts`. Four new golden cases under `fixtures/risk/` run the whole table.
- 464bfe8: Add the `third-party-managers` detector (pivot T1.7): a pure, read-only inventory of repos already managed by another config-sync tool, reported informationally as "managed by X" per ADR-004 - never a finding, never a destructive suggestion. Recognizes Ruler (`.ruler/ruler.toml` + recursive markdown sources + deprecated `.ruler/mcp.json`), rulesync (root `rulesync.jsonc`/`rulesync.local.jsonc`, the `.rulesync/` source tree, feature `.json(c)` files, deprecated ignore files), amtiYo agents-json (`.agents/agents.json` + local split), the agentsync family (`.agents/agentsync.toml`, `.agentsync/agentsync.toml`, `agentsync.config.json`, `agentsync.json`, `.agentsync-state.json`), agent_sync (`.ai/agent_sync.yaml` + `.ai/.sync-manifest`), GowayLee agent-sync (`.agent-sync.toml`), agentlink (`.agentlink.yaml`), the Vercel skills project lock (`skills-lock.json`) and mcp-lock (`.mcp.lock`), plus a symlink-topology scan that maps known agent config paths that are symlinks (a healthy zero-drift pattern) with their literal targets - a link resolving to a directory counts as healthy. Ships four golden fixtures including a Ruler-managed repo, a symlink-managed repo (materialized at test time via a `symlinks.json` sidecar, since git fixture trees cannot carry symlinks portably), and a negative case; exports the ADR-004 `COEXISTENCE_NOTE` for the doctor renderers.

### Patch Changes

- c69eb76: Extract the filesystem plumbing duplicated between the claude-code and codex detectors into a shared internal module (`src/detect-fs.ts`) and their duplicated test wiring into a test-only harness (`src/detect-test-utils.ts`), ahead of the T1.3+ detectors. Internal refactor: no output, fixture, or public API changes.
- 3b32295: Add the first two risk rules to the GM table (pivot §8.1 item 3, T1.11). `GM001` (error) reports a plaintext secret or token in any MCP config, agent settings, hooks or config file: a format-agnostic line scanner matches vendor token shapes (GitHub, GitLab, OpenAI/Anthropic, Stripe, Slack, AWS, Google, npm, Hugging Face, JWT, private-key PEM, credentials in URLs) anywhere on a line and applies a Shannon-entropy gate to values in credential positions - under a credential-named key or CLI flag (`"--api-key", "…"`, `--token=…`) or behind an auth scheme (`Bearer …`) - skipping `${VAR}`/`op://`/placeholder references; findings name the file, line and key and never the value, pinned by a redaction-guarantee test that seeds secrets across JSON, JSONC and TOML and asserts none reaches the findings. Third-party-manager files are scanned too: ADR-004 protects the manager's territory, not a committed token. `GM002` (warning) fires once per agent that can express a `.env` read deny (§10.5) but leaves it exposed: Claude Code without a `permissions.deny`/`ask` `Read(<glob>)` whose glob matches `.env` (`Read(**)` counts, `Read(config/**)` does not), Cursor without a `beforeReadFile` hook, and OpenCode only when `permission.read` resolves a secret path to `allow` under its last-match-wins rules (it denies `.env` by default); Copilot (no hard deny), Codex and Antigravity (command/sandbox controls) are excluded. Copilot's JSONC stripper moves into core as `parseJsonc`, which the copilot detector now imports. Four golden cases under `fixtures/risk/` run the whole table.
