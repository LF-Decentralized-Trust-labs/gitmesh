Add the second pair of risk rules to the GM table (pivot §8.1 item 3, T1.12). `GM003` (error) reports a bypass-permissions / auto-approve / danger-full-access mode in committed config: Claude Code `permissions.defaultMode: "bypassPermissions"` in a project settings file, Codex `sandbox_mode = "danger-full-access"` or `approval_policy = "never"` on a root-table line of `.codex/config.toml` (a mode inside `[profiles.x]` is inert until that profile is selected), and any of VS Code's three `chat.tools.*.autoApprove` keys set to `true` or to an object containing a `true` - findings name the file and key, never pattern values (the T1.4 rule), and only project scope counts (`settings.local.json` hygiene is GM009's lane); cursor (no committed yolo surface), opencode (granular per-pattern grants, not a mode switch - maintainer decision 2026-08-31), antigravity (user-scope surface) and devin are excluded with reasons in the rule doc. `GM004` (warning) reports a skill with executable content and no recognized pin: executable means the detectors' new `executable` stamp - `collectSkillManifests` and the opencode/antigravity skill walks now mark a manifest whose directory holds script files, the adapters' minor bump - or a SKILL.md body that opens a shell code fence or references a script file (`.js` tokens must be path-shaped so prose like "Node.js" never fires); a recognized pin is a key of `skills` in `skills-lock.json` (any version), of `servers` in `.mcp.lock`, or of `skills` in `.gitmesh/lock.json` (honored whenever the caller inventories it; no detector emits it until the T5.x lockfile lands), matching the key or its last `/`-segment for namespaced entries. Per ADR-004 a manager's lockfile presence is never itself a finding and `.ruler/skills/**` sources never enter the rule. `isRecord` moves next to `parseJsonc` in core's `jsonc.ts`. Four new golden cases under `fixtures/risk/` run the whole table.
